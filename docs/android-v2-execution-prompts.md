# Smart Ledger Android APP V2 执行提示词总文档

## 1. 文档用途

本文是 V2 开发的主控文档。每个子步骤都必须单独派发、单独执行、单独复核；未通过主 Agent 验收时不得进入下一步。子任务只能在 `v2-development` 分支的工作副本中工作，不得修改 `v1.0.0-frozen` 标签或冻结基线。

当前 Android APP 使用 Flutter + Dart + 本地 SQLite。V2 仍然保持离线优先，所有输入来源都必须经过“生成建议/草稿 -> 用户确认 -> 正式入库”，不得由导入、OCR 或 AI 直接写入账本。

## 3. 全局不变量

所有子任务都必须遵守：

1. `amount_cents` 是唯一金额真相，使用正整数分；不得引入浮点金额作为持久化值。
2. `type` 只能是 `expense` 或 `income`；`category` 必须使用既有稳定 code。
3. `original_text` 必须保留最初形成该草稿或账目的原始文本，普通编辑不得覆盖。
4. 删除继续使用 `deleted_at` 软删除；列表和统计默认排除已删除记录。
5. 解析结果、导入结果、OCR 结果和 AI 分类结果都只能是草稿或建议，确认前不得写入正式账目。
6. V1 数据必须可读；数据库升级必须是正式 migration，不得删库重建或静默丢字段。
7. 核心记账和已有 V1 功能不依赖网络、FastAPI、localhost、登录或云服务。
8. 不得新增通知、短信、通讯录、无障碍后台采集、支付平台自动读取或未经用户授权的数据访问。
9. 任何新增权限、第三方 SDK、外部服务、数据库字段、数据库表和备份字段，都必须在任务结果中明确说明并附测试。
10. 子任务只能修改提示词中明确授权的文件范围；发现边界不够时暂停并在结果中报告，不自行扩大范围。

## 5. V2.2 统计增强

### V2.2.1 统计数据契约与分类聚合

**提示词：**

> 在不修改 V1 交易字段语义的前提下，新增统计领域模型，表达指定日期范围内的支出总额、收入总额和按稳定分类 code 聚合的分类占比。金额全部使用整数分；分类名称只能从 `CategoryCatalog` 读取。统计必须排除 `deleted_at` 非空记录，并明确总额为 0 时的占比行为。只允许新增或修改 `mobile/lib/domain/statistics/` 与对应 `mobile/test/` 单元测试，不修改 UI、数据库 schema、导入、预算或解析器。验收：覆盖空数据、单分类、多个分类、收入不计入支出占比、软删除排除和整数分精确计算。

### V2.2.2 统计查询与分类读取适配

**提示词：**

> 为 V2.2 统计模型增加本地 SQLite 查询适配，使用现有 `TransactionLocalDataSource`、`TransactionRepository` 和 `Clock` 的模式；查询支持月份或任意半开日期区间，输出分类 code、标签、金额分和占比所需数据。不得重建数据库，不得改变已有查询结果，不得把分类标签写入交易表。只允许修改统计相关 data/repository 文件及对应测试，必要时新增独立统计文件；不得修改首页布局。验收：V1 数据可读取；统计排除软删除；跨月边界正确；无数据不抛异常；查询结果顺序稳定。

### V2.2.3 分类占比页面与入口

**提示词：**

> 在现有 Flutter UI 风格和底部导航结构内增加统计页面，展示当前月份支出总额、分类占比列表和每类金额；使用稳定分类标签，金额显示复用现有格式化工具。页面必须支持加载中、空数据、数据库失败重试和窄屏滚动，不使用复杂图表依赖，不加入余额或消费建议。只修改统计 UI、路由、控制器中统计状态和对应 Flutter 测试；不得修改 V1 编辑、删除、备份流程。验收：真数据库渲染；分类占比总和在有数据时为 100%；软删除不出现；手机窄屏无溢出；错误状态可重试。

### V2.2.4 统计版本验收

**提示词：**

> 对 V2.2 进行独立验收，不新增功能。审查统计计算、SQLite 查询、页面状态、分类 code、软删除、空数据、窄屏布局和 V1 回归。执行相关 `flutter test`、`flutter analyze --no-pub` 和可用的 Android debug 构建；若工具受中文路径影响，记录准确原因并使用 `ascii_mobile` 路径复核。只有测试、diff 范围和产品行为全部通过，才报告 V2.2 可进入下一版本。

## 6. V2.3 预算系统

### V2.3.1 预算数据模型与 SQLite migration

**提示词：**

> 设计并实现最小预算数据模型，支持“分类 code + 月度金额分 + 启用状态/更新时间”，默认每个分类每月一条有效预算。执行正式 SQLite migration，确保 V1 数据库升级后原有交易完整可读，空数据库可直接创建；不得删除或重建 `transactions` 表。明确备份版本兼容策略，至少保证旧 V1 JSON 备份可以恢复，预算缺失时按无预算处理。只修改数据库 schema、预算领域/data 文件和对应 migration/测试文件，不做预算 UI。验收：V1 数据库升级测试、预算 CRUD 校验、金额整数分、分类与支出类型校验、重复月份分类处理、旧备份恢复不丢交易。

### V2.3.2 预算计算与预计用完日期

**提示词：**

> 基于预算模型和现有交易统计，新增预算服务：计算指定月份每个预算分类的预算金额、已使用、剩余、超支金额、当前状态，以及按本月日均支出估算预计用完天数。计算必须排除软删除和收入，月初/月底、没有消费、预算为 0、已超支和不足 1 天等情况必须有明确规则；预计只作为提示，不改变账目。只修改预算领域服务和单元测试，不改 UI、不接网络。验收：固定时钟下结果可重复；金额不使用浮点持久化；边界月份正确；超支状态不会被负剩余吞掉。

### V2.3.3 预算页面和首页提醒

**提示词：**

> 增加预算管理页面和首页预算摘要。用户可以新增、编辑、停用分类月预算；页面显示“已使用、剩余”，超支使用红色提醒，能显示预计用完天数但不得伪装成精确预测。所有保存都经过校验，错误可见，加载失败可重试，手机窄屏可滚动。只修改预算 UI、路由、控制器状态和对应 Flutter 测试；不修改已有记账编辑器和交易表字段。验收：真实 SQLite 往返；预算保存后统计联动；超支红色状态；删除/停用预算不删除交易；返回页面不丢草稿。

### V2.3.4 预算版本验收

**提示词：**

> 对 V2.3 做发布级审查，重点检查数据库 migration、V1 JSON 备份兼容、预算计算边界、软删除、超支提示、日期时钟、错误恢复和手机布局。执行全量 Flutter 测试、分析和可用的 Android 构建。发现 migration 会清空数据、预算绕过确认或预测结果无依据时，立即判定不通过并停止后续版本。

## 7. V2.4 微信账单 CSV 导入

### V2.4.1 通用导入草稿契约

**提示词：**

> 设计通用账单导入契约，表达文件来源、原始行、日期、金额、收支方向、商户/备注、分类建议、解析问题、重复提示和确认状态；导入结果必须复用批量确认语义，不能直接写入 SQLite。优先使用现有 `BatchParseResult`/`BatchTransaction` 语义，避免复制 V1 校验。只新增导入 domain 文件和纯单元测试，不接文件选择器、不加平台权限。验收：有效、缺日期、金额格式异常、退款/收入、未知商户、重复候选和空行都能保留并明确状态。

### V2.4.2 微信 CSV 解析器

**提示词：**

> 实现微信账单 CSV 解析器，支持 UTF-8/UTF-8 BOM、带引号逗号、换行、空列和常见中文表头；只根据文件内容解析，不假设固定列序。识别交易时间、交易类型、收支、金额、商品/商户、交易单号等可用字段，金额转换为整数分，退款和收入不得默认为支出。使用分类目录和本地规则生成分类建议，无法确认时保留阻塞或待确认问题。只修改微信导入 domain 文件和测试，不修改数据库/UI。验收：真实样例夹杂表头和说明行可解析；引号逗号不破列；金额精确；坏行不导致整文件静默丢失。

### V2.4.3 文件选择与导入确认页

**提示词：**

> 在 Flutter Android 中增加本地 CSV 选择入口和导入确认页。文件读取必须由用户主动选择，导入前显示文件名、解析统计、错误行、重复提示和可导入条目；确认后才调用批量保存。若当前依赖没有文件选择能力，先提出最小依赖和 Android 权限影响，再按已批准依赖实现，不得偷偷接云盘或读取其他 APP。只修改导入 UI、路由、控制器和对应测试。验收：取消选择不改账；解析失败可重试；存在错误行时不可误导用户一键入库；确认保存保持整批事务语义。

### V2.4.4 微信导入版本验收

**提示词：**

> 对 V2.4 做独立发布验收：检查 CSV 解析兼容性、文件权限、编码、金额、日期、退款/收入、原始文本追溯、批量确认、整批失败回滚、重复导入提示和手机布局。执行全量测试、静态分析和 Android 构建；不得把“能读取文件”当作“能安全入账”。任何自动入库、静默丢行或来源数据泄露都判定不通过。

## 8. V2.5 支付宝账单 CSV 导入

### V2.5.1 支付宝格式适配器

**提示词：**

> 复用通用导入契约和文件选择流程，新增支付宝 CSV 格式适配器。处理支付宝常见的表头说明行、交易时间、交易分类、收/支、金额、交易对方、商品说明、交易订单号和资金状态；只把成功且可确认的交易生成候选，关闭/失败/不计入账单的状态必须明确跳过原因并保留统计。只修改支付宝导入 domain 文件和测试，禁止复制微信解析器的大段逻辑。验收：格式差异通过适配器隔离；退款和收入方向正确；订单号或原始行可追溯；坏行有行号和原因。

### V2.5.2 支付宝导入 UI 集成

**提示词：**

> 将支付宝导入接入现有导入入口，允许用户选择来源后选择 CSV，并复用同一确认页、错误展示、重复提示和批量保存接口。不得新增第二套保存链路，不得绕过用户确认。只修改导入来源选择、路由/控制器和 Flutter 测试，保持微信功能回归通过。验收：微信与支付宝可以分别解析；取消/失败不改数据库；确认后整批保存；原始文本和分类建议可追溯。

### V2.5.3 导入数据与备份验收

**提示词：**

> 审查支付宝导入与微信导入的共同安全边界、重复处理、备份兼容、软删除统计、分类 code、导入文件残留和权限声明。执行全量 Flutter 测试、静态分析、Android 构建和至少一轮真实样例回放。任何导入文件被长期复制到应用数据之外、任何导入直接改写历史账目或任何旧备份无法恢复，都必须阻止版本通过。

## 9. V2.6 OCR 与 AI 分类输入

### V2.6.1 OCR 服务契约与本地实现

**提示词：**

> 设计 OCR 输入契约，表达原图来源、识别文本、文本块/行、置信度、候选问题和处理状态；OCR 只产出文本或草稿，不直接写账。优先采用 Android 可离线运行的 OCR 能力，明确相机/相册权限、原图保存策略、隐私提示和失败回退；不得把图片或文字上传云端。先只新增 OCR domain/provider 抽象和测试，平台实现另行处理。验收：文本为空、低置信度、多行小票、数字/单位粘连、识别失败均有可观察状态；无权限时不崩溃。

### V2.6.2 小票拍照与批量草稿

**提示词：**

> 增加拍照/选择小票图片入口，调用已批准的本地 OCR provider，将“白菜10、牛奶15、饮料8”等识别行转换为批量草稿，并复用 `MultiTransactionParser` 和 `BatchConfirmPage`。相机或相册只在用户主动操作后访问；取消、拒绝权限、图片损坏、OCR 失败都必须可恢复。确认前不写库，不保存无必要的原图。只修改 OCR UI、路由、控制器和对应测试，保持 V1 与批量记账回归。

### V2.6.3 AI 分类输入

**提示词：**

> 实现“蜜雪冰城 12 -> 餐饮”“中国石化 300 -> 车辆/加油”的分类输入能力。默认使用本地确定性规则和现有 `ClassificationService` 扩展，不接云端大模型、不发送用户文本、不自动入库；输出分类建议、规则命中依据和待确认状态，无法判断时回退其他支出并提示用户。只修改分类 domain/parser 文件和对应单元测试，保持既有分类 code 不变。验收：示例输入分类正确；分类冲突可见；用户可在确认页修改；规则不会把金额或日期误当分类。

### V2.6.4 OCR/AI 统一确认流程

**提示词：**

> 将手工输入、批量输入、CSV 导入、OCR 和 AI 分类统一到草稿确认边界，禁止来源各自写库。补齐加载、处理中、失败、空结果、部分成功、用户取消、重复候选和保存失败状态；确保原始文本追溯、整数分、稳定分类和软删除统计不变。只修改跨来源编排、确认页适配和集成测试，不重新设计 V1 数据模型。验收：所有来源都能进入确认页；任一候选错误不会静默入库；整批保存失败不会留下半批数据。

### V2.6.5 最终发布验收与安装包

**提示词：**

> 按真正可发布的 Android APP 标准完成最终 review，不新增功能。检查 V1 回归、批量记账、搜索、分类统计、预算、微信 CSV、支付宝 CSV、OCR、AI 分类、数据库 migration、备份恢复、权限、隐私、错误恢复、手机窄屏和旋转/返回行为。执行全量 `flutter test`、`flutter analyze --no-pub`、Android release 构建、APK 安装验证和关键流程真机 UAT；记录构建产物路径、版本号、权限清单、已知限制和发布阻塞。任何核心流程崩溃、数据丢失、自动入库、旧数据不可读或权限说明不一致，都必须判定未发布。

## 10. V2.6 冻结结论

## 11. 并发与串行规则

可以并行：

- V2.2.1 统计领域模型与 V2.4.2 微信 CSV 解析器。
- V2.4.2 微信 CSV 解析器与 V2.5.1 支付宝适配器，但支付宝只能依赖通用导入契约。

- OCR provider -> 拍照入口 -> 统一确认流程 -> 最终发布验收。
- 任一版本的实现任务必须在主 Agent 复核通过后，才能进入下一版本。
